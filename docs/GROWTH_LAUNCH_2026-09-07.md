# Music Spot 초기 이용자 확보 실행안

## 확인한 사실과 판단

2026-09-07 공개 anon API로 집계: 공개 연습실 1,008개, stem_projects 5개, user_profiles 8개, posts 11개. 운영·시드 데이터가 포함될 수 있으며 활성 이용자 수가 아니다. 기존 공개 홈에서도 검색 선택값이 전달되지 않는 UI와 잘못된 푸터 링크를 확인했다.

현재 가설: 이미 공급이 있는 연습실 검색을 첫 사용 이유로 삼고, 실제 합주팀이 유용함을 느낀 다음 8마디 릴레이로 초대한다. 기능을 더 늘리거나 가입자 수를 부풀리는 것을 목표로 삼지 않는다. 아래 수치는 예측이 아닌 14일 실험의 판정 기준이다.

## 이번 코드 반영

- 홈 검색을 Hero 바로 다음으로 배치. 지원하지 않는 날짜·시간·인원 선택을 지역·시간당 예산·드럼 조건으로 교체하고 URL에 전달.
- 실제 검색 총수, 일관된 정렬, 연속 검색 응답 역전 방지, 실패 안내·재시도, 더보기 실패 시 페이지 건너뜀 방지.
- GPS에서도 동일한 조건 적용. 200개 RPC 상한 대신 1,000개 배치 조회 후 거리 필터. 데이터 증가 시 서버의 필터 가능한 RPC로 최적화 필요.
- 빈 결과에 조건 초기화·지역 탐색 제공. 푸터 잘못된 이동과 # 가짜 링크 제거.
- 캠페인 UTM을 탭 세션 내 유지해 내부 이동 후 문의·가입까지 출처 연결.

## 14일 실행 순서

1. 배포 후 운영 도메인에서 홍대/강남 검색, 상세, 업체 원문 링크, 로그인 복귀를 점검한다. 허위 가격·폐업·사진 오류 제보 동선도 확인한다.
2. 홍대·강남 중 실제 검색 품질이 나은 한 지역으로 시작한다. 상위 10개 업체의 원문에서 연락처·가격·운영 상태를 수동 확인하고 확인일을 남긴다. 검증 전에는 ‘예약 가능’이나 ‘최저가’를 광고하지 않는다.
3. 사용자가 직접 운영하거나 홍보가 허용된 밴드/동아리 채널 2곳에 아래 문안을 게시한다. 자발적인 테스터 10명을 모집한다. 각자 현재 실제로 잡아야 하는 합주 1건에 사용하도록 요청한다.
4. 첫 3일은 검색→상세→업체 문의에서 막힌 이유를 수집한다. 성공한 이용자에게만 팀원에게 링크 공유를 부탁한다.
5. 4~7일: 문의를 해본 팀 3개에게 자기 팀의 오리지널 리프 8마디를 올리고 팀원이 이어 녹음하는 실험을 제안한다. 공개 챌린지의 공급 부족을 해결하는 작은 단위다.
6. 8~14일: 아래 지표를 비교한다. 채널별 표본이 20세션보다 적으면 우열 결론을 내리지 않고 모집을 이어간다. 문의가 없는 채널은 홍보량 대신 랜딩·검색 품질을 먼저 점검한다.

## 성과 판정

| 지표 | 정의 | 14일 실험 기준 |
| --- | --- | --- |
| 유효 유입 | 지정 campaign의 서로 다른 session_id | 50세션 |
| 첫 효용 | studio_view 이후 같은 세션에서 contact_click | 10세션 |
| 실제 이용 | 테스터가 업체 문의/방문했다고 자발적으로 확인 | 3팀 |

contact_click은 문의 버튼 클릭일 뿐 예약 성사가 아니다. sessionStorage ID는 탭 단위이므로 사람 수나 D7 리텐션으로 해석하지 않는다. 운영자·QA 캠페인은 별도 분리한다. 최초 캠페인이 없는 과거 이벤트에 출처를 소급 복원할 수는 없다.

분석 SQL: `scripts/growth-funnel.sql`. 읽기 전용이며 아직 실행하지 않았다.

## 완료와 남은 작업

코드 수정과 로컬 검증은 진행했으나 운영 배포·게시·이용자 모집은 수행하지 않았다. 공개 게시와 DM 발송에는 대상과 문안에 대한 사용자 승인이 필요하다. 실제 개인정보처리방침·약관 문서도 제공되지 않아 가짜 # 링크는 제거했으며, 운영자가 제공하는 실제 문서를 연결해야 한다.
