# 에이전트 인수인계 (Claude Code ↔ Claude Cowork)

> **이 파일을 연 에이전트는 아래 규칙을 지시로 따른다.** (Claude Code·Claude Cowork 공통, 사용자 지시가 우선)
> 사람이 같은 내용을 두 번 설명하지 않게 하는 통로다. 지금 상태 요약은 `docs/PHASES.md` 맨 위 "현재 상태".

## 규칙

**작업 시작할 때**
1. 이 파일의 맨 위 항목 3개를 읽는다. `상태: 열림`이고 `받는 쪽`이 나인 항목이 있으면 그 요청부터 처리하거나, 못 하면 이유를 적는다
2. `docs/PHASES.md` 맨 위 "현재 상태"를 읽는다
3. (Claude Code) `git status` · `git log -5`로 상대가 남긴 커밋 안 된 변경이 있는지 본다. 이 파일 항목과 맞지 않는 변경은 지우지 말고 사용자에게 묻는다

**작업 끝낼 때 (파일을 하나라도 바꿨거나, 조사·결정 결과가 있으면)**
1. 아래 "기록" 맨 위에 항목을 추가한다 (최신이 위)
2. 운영 상태·다음 할 일이 바뀌었으면 `docs/PHASES.md` "현재 상태"도 고친다
3. 상대에게 넘길 일이 있으면 `받는 쪽`과 `요청`을 적고 `상태: 열림`. 처리한 쪽이 `상태: 처리됨 (YYYY-MM-DD, 누가)`로 바꾼다

**둘 다 지킬 것** (`CLAUDE.md`·`docs/RULES.md` 요약)
- PR 머지·main 푸시·운영 DB 쓰기·스키마 변경·환경변수 변경은 **사용자가 그때 지시할 때만**
- 비밀값(비밀번호·키·토큰)은 이 파일·문서·커밋 어디에도 쓰지 않는다
- QA는 `utm_campaign=codex_qa` 표시
- 커밋을 안 하는 쪽(Cowork)은 바꾼 파일 경로를 빠짐없이 적는다 → Claude Code가 리뷰·커밋·PR을 이어받는다

## 항목 형식
```
### YYYY-MM-DD HH:MM KST — <작성자: Claude Code | Cowork> — <한 줄 제목>
- 한 일:
- 바뀐 파일: (경로 · 커밋/PR 번호, 커밋 안 했으면 "커밋 안 함")
- 확인한 것: (실행한 명령·결과, 못 한 확인)
- 받는 쪽: Claude Code | Cowork | 사용자 | 없음
- 요청: (받는 쪽이 할 일. 없으면 "없음")
- 상태: 열림 | 처리됨 (날짜, 누가)
```
